3번 과제입니다. 메인 장소/서브 리뷰 다큐먼트 PUT 요청을 처리하는 컨트롤러 상-변수인 locationsUpdate, reviewsUpdate를 만든 틀을 가지고 완성하게 되었습니다.
사실 POST와 그렇게 큰 차이는 없는 것같지만, 정보만을 업데이트하는 것이 큰 차이입니다.

locationsUpdate부터 설명하겠습니다.
당연하지만, req.params, URL 파리미터에 locationid가 없으면 안되므로 이를 if문에서 처리하게 했습니다.
만약 존재하지 않는다면 404 에러 코드와 json 에러 메시지로 locationid가 없다고 알려주게 했습니다.

만약에 존재한다면 아래에 있는 try-catch문으로 들어가게 됩니다.
location이라는 const 상-변수를 만든 뒤, findById 메서드에 전달받은 id를 넣은 뒤 -reviews -rating을 select 메서드에 넣어서
reviews, rating 부분을 제외한 나머지 부분들만 사용하게 데려옵니다. (제외한 부분은 reviewsUpdate에서 따로)

만약에 location이 존재하지 않는 경우를 방지하기 위해 if (!location) 문을 둬서 여기 걸리면 location이 제대로 존재하지 않는다는 뜻이니
404 에러 코드와 json 에러 메시지로 locationid로 찾을 수 없다고 알려줍니다.

if문을 통과하면 req.body에 있는 우리가 기재한 추가할 데이터들을 locationsCreate와 마찬가지로 똑같이 각각에 매칭되는 정보 변수에 넣어주면 됩니다.
전부 넣어준 뒤, updatedLocation이라는 const 상-변수에 location.save() 메서드로 이 모든 변경 사항이 저장된 location을 저장한 뒤,
만약에 문제가 없었다면 return res문으로 들어가 200 상태 코드와 json으로 객체를 출력하게 했고,
문제가 중간에 있었다면 catch문에 err가 들어가 400 에러 코드와 err 자체의 정보가 출력되도록 만들었습니다.\

reviewsUpdate는 메인 문서와 서브 문서를 명시할 수 있는 것이 모두 필요하므로
if문에서 req.params에 locationid나 reviewid가 하나라도 없다면 404 에러 코드와 "locationid와 reviewid가 가져와지지 않음"이라는 메시지를 출력하게 했습니다.

둘 다 존재한다면 try-catch문으로 들어가게 됩니다.
아까와 똑같이 location이라는 const 상-변수를 만든 뒤, findById 메서드에 전달받은 id를 넣되, 이번에는 reviews를 select 메서드로 데리고 옵니다.
다음으로 if문에서 location이 존재하지 않는 조건에 걸리면 404 에러 코드와 json 에러 메시지가 출력되게 했습니다.

만약 그렇지 않다면 다음 단계의 if문에서 location의 reviews가 실존하고, 1개 이상인 지를 검사한 뒤,
만약 실존하지 않거나, 0개라면 else문에서 404 에러 코드와 json 에러 매시지가 출력되게 했습니다.

검사를 통과했다면 thisReview라는 const 상-변수를 만든 뒤, location.reviews.id 메서드에 req.params에 있는 reviewid를 매개변수로 넣어 우리가 변경할 리뷰가 지정되게 합니다.

그 다음 또 if문에서 thisReview가 실존하는 지 확인한 뒤, 실존하지 않다면 404 에러 코드와 json 에러 메시지로 리뷰를 찾을 수 없다고 알려줬습니다.
이후 찾은 리뷰의 author, rating, reviewText를 req.body(Form)에 있는 매칭되는 데이터로 모두 각각 업데이트한 뒤,
location.save 메서드로 이 모든 결과를 저장한 뒤, updatedLocation이라는 const 상-변수에 저장시킵니다.

다음으로 바뀐 리뷰에 따라서 레이팅이 달리지니 updateAverageRating 함수를 데리고 온 뒤, id를 전달하여 레이팅 업데이트가 정상적으로 이루어지게 합니다.
아까 만들어뒀던 함수가 잘 사용되는 모습이죠.

이 모든 과정이 잘 이루어진다면 return res문에서 200 상태 코드와 json 메서드로 업데이트가 끝난 thisReview를 출력하게 될 것입니다.
중간에 오류가 생긴다면 err를 감지하고 catch문에서 return res문으로 이어져 400 에러 코드와 err 자체 정보를 출력하게 됩니다.

이를 통해서 업데이트가 됩니다.
