지난 번 API의 틀을 모두 만든 뒤 본격적으로 GET, POST, PUT, DELETE,
총 4가지의 REST API 처리 작업을 구현하기 위해서 GET부터 구현하기 시작하는 과제였습니다.
api 폴더의 locations.js에 만들어둔 locationsReadOne 컨트롤러에
이제 틀 대신 Promise 기반의 async/await 기반의 응답 처리 함수를 만들었습니다.

findById에 URL에 우리가 입력한(나중에는 버튼 누르면 자동으로 하게 할)
locationid를 전달하여 DB에서 이를 찾도록 타깃을 잡아주고,
exec에서 이를 처리합니다. 처리 후에는 location에 이를 저장합니다.
예) const location = await Loc.findById(req.params.locationid).exec();

*일반적으로 URL의 사용되는 파라미터들은 req.params에 저장됩니다.

응답을 res로 보낼 때 status 메서드로 200을 보내게 하고,
json 메서드로 DB에서 가지고 온 location 정보를 출력하게 했습니다.
예) res.status(200).json(location);

만약 err가 난다면 catch 문에서 이를 처리하도록 했고
이 경우 status 메서드로 500을 보내게 하고, json 메서드로는
에러 메시지를 출력하도록 했습니다.
예) res.status(500).json({ error: 'An error occured.' });
.json의 매개변수에 그냥 err를 표시하면 에러 정보를 출력시킬 수 있습니다.
메시지나 에러 정보 두 방식 모두 사용할 때가 많습니다.

이후 MongoDB Compass에서 스타벅스 장소 ID를 가지고 와서
URL에 직접 명시한 뒤 GET 요청을 해당 URL을 통해서 보내어 테스트한 결과,
정상적으로 ID에 맞는 DB 장소 데이터 정보가 출력되는 걸 확인하실 수 있습니다.
