마지막 과제입니다. 마지막 과제는 포매팅은 존재하는 "장소"에 일어나야하므로 if문을 둬서 "장소"가 존재하는 지 검사한 뒤 포매팅을 적용하게 하는 것과
쿼리 스트링에 의해서 검색되는 "장소"가 발견되지 않아도 200 정상 상태를 반환하는 걸 수정하여
"장소" 배열 자체가 오지 못하는 오류나, "장소" 배열이 공백으로 오는 경우를 해결할 수 있게 하는 과제였습니다.

먼저, 포매팅을 if문으로 "장소"가 1개 이상 검색되었을 때만 진행되게 하는 것은
포매팅 함수 호출 및 사용-저장문을 if문으로 묶기만 하면 됩니다. 내부 조건은 statusCode === 200 && body.length,
이는 엄격하게 검사하여 상태 코드가 200과 동일하고, body.length가 존재할 때, 즉 배열이 존재할 때(배열이 존재하지 않으면 length 자체가 없다.)를
뜻합니다. 따라서 에러가 나거나 "장소" 자체가 존재하지 않는 경우라면 이제 포매팅을 진행하지 않게 됩니다.

다음으로 응답 바디의 나머지 경우인 어떤 장소도 없는 공백 배열 응답과 에러 메시지 응답 파트에도 적절한 처리 동작을 추가하게 했습니다.
이전까지는 이런 케이스에서도 정상적으로 출력을 할려고 해서 그냥 장소가 안뜨기도 했는데 사용자 입장에서 이상하므로
에러 상황일 때는 에러 메시지를, 좌표에 가까운 장소가 없는 경우의 응답에는 근처 장소가 없다는 메시지가 출력되게 했습니다.

내부 조건은 다음과 같습니다.
renderHomepage를 function 함수로 만든 뒤, 렌더링 render 메서드 위에 다음을 추가합니다.
출력될 메시지가 될 message를 null로 생성한 뒤 if문을 한번 만나게 합니다.
해당 if문의 조건은 !(responseBody instanceof Array)로, 응답 데이터로 오는 responseBody가 Array, 즉 배열이 아니라면 이라는 조건입니다.
이 조건은 응답 데이터로 오는 responseBody가 배열이 아니라면 불량이라는 것을 암시하므로 에러 메시지 응답 파트입니다.
이 경우 if문 내부로 들어가서 message에 "API lookup error"라고 저장한 뒤 responseBody를 공백 배열로 초기화시키게 했습니다.

그렇지 않다면 else문에 걸려서 2차 if문 검사를 받게 됩니다. 내부 조건은 !responseBody.length 입니다. responseBody의 length가 존재하지 않는다면 이라는
조건입니다. 이는 공백 배열이라면 length가 존재하지 않기 때문에 length의 존재 여부를 가지고 조건을 사용할 수 있습니다.
만약 if문 내부로 들어오면 message에 "No places found nearby"라고 저장한 뒤 마치게 됩니다.

모든 if문에 걸리지 않았다면 정상 상황이라 이미 만들어둔 대로 잘 출력되게 될 것입니다.
이제 message를 추가 출력해야하니 기록하여 출력 공간인 location-list로 가기 전에 공간 이름에 s를 첨가하여 추가했습니다.
다음으로 교수님께서 알려준 위치에 .error=message를 추가하여 잘 마무리했습니다.

마지막으로 requestOptions의 qs를 주어진 것으로 조작하여 의도한 대로 위도 1 경도 1 0.002m 방면의 장소로 테스트했습니다.
당연히 그런 장소는 여기 DB에는 존재하지 않을 것이기에 공백 배열이 나올 것이었고
직접 확인해보니 이에 따른 메시지인 No places found nearby이 정상 출력됨을 확인하실 수 있습니다.
