첫번째 과제입니다. 우리가 만든 API를 토대로 이제 사이트에서 이를 사용하여 데이터를 불러와서 출력시킬 수 있게 해주는 실습 과제입니다.
기존 renderHomepage 컨트롤러를 수정하여 더 이상 우리가 직접 사이트 정보를 기재하지 않고 DB에서 데이터를 가져올 수 있게 했습니다.

먼저, api를 사용하기 위해서 요청 API인 request를 설치한 후 서버의 locations.js에서 사용할 수 있도록 request라는 변수로 가져왔습니다.
한편, api 사용을 위한 옵션으로 apiOption이라는 상-변수를 만들어 필요한 정보들을 기입합니다.
특이한 건 API 콜을 하기 위한 모든 컨트롤러는 어떤 환경인지 확인하는 일을 피하기 위해 디폴트 설정 옵션을 설정할 수 있습니다.

apiOptions에 server, 서버 주소와 if문을 달아 process.env.NODE_ENV가 production, 즉 제품 환경이라면
server는 'https://yourapi.com"으로 쓰이도록 했습니다. 따라서 제품 환경이 아니라면 일반 서버 주소를 사용하고 아니라면 이 주소를 사용하게 했습니다.
일반 서버 주소는 'http://localhost:3000'입니다. 우린 아직 저 일반 서버 주소를 쓰는 편이 많죠.

다음으로 요청을 할 때 옵션을 requestOptions로 지정했습니다.
내부 내용은 다음과 같습니다. 어디서 데려올 지 url을 지정했습니다. 우리가 위에서 지정한 server 주소 자체가 url입니다.
method는 내용을 가져오니 'GET', json 객체는 사이트에 있던 오리지널 데이터가 필요 없으니 공백으로 해뒀으나 qs, 즉 쿼리 스트링으로는
lng와 lat에 제 집 좌표를, maxDistance는 200000으로 반경 200km의 장소들을 찾아 띄우게 정하여 요청에 사용되도록 만들었습니다.

다음으로 이러한 요청 옵션을 가지고 요청이 진행되게 하는 부분입니다.
request 객체에 requestOptions가 들어가게 하고, 뒤에서 무명 함수 하나를 전개합니다.
err, response, body를 받아들이는 이 무명 함수는 renderHomepage에 이 세 가지를 모두 넘깁니다.
err는 에러 시 생기는 에러 객체, response는 응답 상태 메시지를, body는 전달받는 JS 객체들을 뜻합니다.
이후 renderHomepage에서 작업을 이어가게 만들었습니다.

renderHomepage는 메인 홈페이지를 렌더링하여 pug 창에 띄워주고 덮어씌워줍니다.
달라진 점은 title, pageHeader, sidebar는 별도의 변경 없이(똑같이) locations에 직접 다 작성하던 장소 정보 코드들을 
모두 단 한 코드인 locations: responseBody라고 바꿔서 적용시켰습니다. 전달받은 JS 객체에 해당하는 responseBody에
쿼리 스트링으로 지정한 집 좌표 근처의 장소들 데이터가 들어있게 될 것입니다. 에러가 나지 않아야하겠지만요.

정리하면 다음과 같습니다.
homelist 컨트롤러에서 url, method 등등 요청에 필요한 정보들을 만들어서 requestOptions라 묶고, 묶은 정보를 request 함수에 전달,
request라는 함수는 requestOptions를 가지고 요청 실시, 요청 과정에서 err, response, body에 해당하는 것을 받아 모두 
renderHomepage 함수에 넘깁니다. renderHomepage는 render 메서드에 title, pageHeader, sidebar 같은 정형화되고 내용이 어느 정도 짧은 것들을
그대로 두고, locations: responseBody 라고 해서 더 이상 하드코딩하지 않고 장소 데이터를 데리고 와서 출력시키게 했습니다.
이를 통해서 이제 메인 홈페이지의 장소는 쿼리 스트링에 따라 DB에서 데이터를 불러와서 출력시키게 했습니다.
