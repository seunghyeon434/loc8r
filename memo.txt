두번째 과제입니다. 그동안 설정한 Add Review 페이지를 가지고 이제 리뷰 추가 기능을 구현하는 파트입니다.
doAddReview에서 리뷰 추가 기능을 담당합니다.

URL에서 location ID를 가져와 호출 URL을 만들고 폼에 게시된 데이터를 가져와 패키지화한 뒤 호출하여 보내서 리뷰를 추가하는 방식입니다.
성공 시에는 리다이렉트로 "장소" 페이지로 이동하여 새로 추가된 리뷰를 보여주고, 아니라면 에러 페이지를 보여주는 방식입니다.

폼 사이트에서 입력하는 데이터는 각각 name, rating, review, 그에 매칭하는 API 요소는 author, rating, reviewText입니다.
doAddReview 컨트롤러에서 이 매칭된 요소를 postdata라는 상-변수에서 매칭시켜서 구조화를 시켰습니다.

컨트롤러의 구조는 다음과 같습니다.
locationid에 URL 파리미터의 locationid를 지정하고, path에는 `api/locations/${locationid}/reviews`를 지정한 뒤,
postdata가 있고, 아래에는 requestOptions로 요청 옵션을 지정합니다.
url에 apiOptions.server에 있는 서버 파트와 path를 합쳐서 지정한 뒤, method는 POST로 둡니다.
POST 요청의 경우 이에 필요한 json 객체가 있고 우리가 보낼 객체는 postdata, 즉 폼의 데이터를 기반으로 만든 json 객체죠.
이 객체를 보냄으로써 DB에 리뷰로써 추가되게 할 것입니다.

request 파트입니다.
requestOptions와 뒤의 콜백 함수로 구성됩니다.
요청 시 requestOptions의 정보들로 요청을 실시하고, 그 실시 후 콜백 함수가 작동됩니다.
내용은 다음과 같습니다. statusCode를 콜백 함수에서 감시하여,
만약에 201이 정확히 맞다면 (===) res.redirect 메서드를 통해서 /location/${locationid}로 돌아가게 하여
기존 "장소" 사이트로 재이동시켜서 추가된 리뷰를 보게 만들게 if문을 사용하였습니다.
if (statusCode === 201) { res.redirect([경로 부분]);} 

else문에서는 showError 함수를 호출하여 에러 사이트를 띄우게 했습니다.
왜냐하면 201이 아니랴면 정상적인 POST 요청에서 벗어난 이상현상/에러이기 때문입니다.

출력 사진에서 보실 수 있듯이 이제 리뷰 폼 사이트를 통해서 정상적인 리뷰 추가가 되는 것을 보실 수 있습니다.
