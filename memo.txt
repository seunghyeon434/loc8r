다음은 서브 다큐먼트, 즉 리뷰에 대해서 GET 요청을 수행할 수 있게 하는 작업입니다.
비슷한 흐름으로 가되, 부모 다큐먼트, 즉 장소 문서에 대해서 찾기 작업이 필요합니다.
따라서 이를 위해서 select 메서드를 데리고 왔습니다.

findById에 select 메서드를 연결하여 name, reviews를 데리고 오게 했습니다.
예) const location = await Loc.findById(req.params.locationid).select('name reviews').exec();

이후 똑같이 if (!location) 문으로 장소 정보가 정상적으로 저장되지 않아
location 안이 텅 빈 상황을 404 에러 + 메시지 출력으로 처리하고,
다음으로는 if (location.reviews && location.reviews.length > 0) 문으로 가게 됩니다.
이 조건의 뜻은 "리뷰 모임" 부분이 존재해야하고, 리뷰가 1개 이상 있는 지 확인하는 것입니다.
리뷰가 존재하지 않는다면 한참 밑에 있는 else문으로 들어가게 하여 404 에러 + 리뷰들 자체가 없다는 메시지를
출력하도록 만들었습니다. 

리뷰가 존재한다면 if문 내부로 들어가서 두번째 처리 과정을 거칩니다.
리뷰들이 존재해도 우리가 원하는 리뷰는 존재하지 않을 수 있습니다.
장소와 마찬가지로 review라는 const 타입의 상수-변수를 만들되,
locations.reviews.id 메서드로 URL에 우리가 기재할(버튼같은 걸 누르기로 추가할)
reviewid를 매개변수로 받아 이에 해당하는 리뷰를 찾아서 저장하게 합니다.
예) const review = location.reviews.id(req.params.reviewid);

그런데 우리가 기재한 id에 해당하는 리뷰가 없을 수 있으므로
이를 if (!review) 문으로 처리합니다.
만약 여기에 걸린다면 우리가 원하는 리뷰가 없다는 점에서 이를 처리하여
404 에러와 리뷰를 찾을 수 없다는 메시지를 출력하게 했습니다.
마찬가지로 status, json 메서드가 쓰입니다.

리뷰가 정상 존재하는 지를 확인했다면 그 아래는 response 부분입니다.
이제 응답으로 쓸 상수-변수를 const형으로 만들게 됩니다.
내부 구조는 당연히 location, 장소 부분이 있습니다.
name과 id를 만들고 각각 location.name과 URL 파라미터의 locationid가
들어가게 했습니다. 그리고 다음에는 review를 기재하여 응답으로는 결국,
장소와 리뷰가 가게 했습니다.
예) const response = { location: { name: location.name, id: req.params.locationid }, review };

이후 아래에서 return res문을 지나게 하여 200 상태 코드와 response를 출력하게 했습니다.
이러면 정상 응답 상황입니다.

마지막으로 이 모든 상황이 try문에서 일어나는 데 기재하지 않은 에러 상황이 터질 시,
catch문에서 그 에러를 err로써 처리해서 400 에러 코드와 err 에러 자체를 출력하게 했습니다.

한편, 리뷰를 다루는 reviews.js에도 리뷰를 만드는 컨트롤러, 업데이트하는 컨트롤러,
삭제하는 컨트롤러가 틀로써 존재하고 exports에서 가져오는 컨트롤러를 포함하여
모두 바깥에서 사용할 수 있도록 하고 있습니다.

출력 화면에서 이제 리뷰 서브 다큐먼트도 정상적으로 GET 요청 처리를
하고 있음을 확인하실 수 있습니다.
