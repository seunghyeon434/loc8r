네번째 과제는 에러 사이트 방식 대신 사이트 이동 없이 경고문으로 알려주는 유효성 검사 출력 방식을 사용하는 과제입니다.
스키마 레벨에서 일반적으로 유효성 검사 비통과 에러는 ValidationError라는 이름을 가집니다.
따라서 statusCode가 400이고, name이 존재하면서 ValidationError면 유효성 검사 비통과 에러라는 뜻이라,
이 조건을 그대로 doAddReview의 request 요청 내 if-else if-else의 else if 조건에 추가하여 해당 에러를 걸러낸 뒤,
에러에 대해서 redirect 메서드로 다시 해당 "장소"에 대한 리뷰 추가 사이트로 돌려보내되, 끝에 쿼리 스트링으로 err=val을 추가했습니다.
이는 기존 "장소" 추가와는 다른 문제 상황으로 왔다는 것을 알리고, 그에 대한 사이트 처리를 위해서 존재하는 추가 정보입니다.
redirect 메서드에는 다음이 기재됩니다. `/location/${locationid}/review/new?err=val`

쿼리 스트링의 존재를 확인하기 위해서는 이에 대한 변수가 필요하여 renderReviewForm에서 error를 따로 지정하여,
여기에 req.query.err를 지정하여 에러를 저장시켰습니다.
이 저장한 에러는 location-review-form에서 '-' 기호를 통해 JS 문법을 도입시킨 뒤, if문을 사용하여 출력되게 만들 수 있습니다.
표현문을 구현하는 데에 부트스트랩 alert 컴포넌트를 사용하여 형태 있게 구현했습니다.

- if (error == "val) 
  [alert 부트스트랩문 및 내용]

이런 방식입니다. 내용은 경고문의 내용이 됩니다.
내용에 영문을 채워서 출력 화면에서 채운 영문의 경고문이 뜨는 것을 확인하실 수 있습니다.
뜻은 "모든 필드가 required, 다시 시도하세요" 라는 뜻입니다.

출력 화면에서 정상적으로 유효성 검사에 의해 경고문도 잘 뜨는 것을 확인하실 수 있습니다.
