2번 과제입니다. 서브 다큐먼트 POST 요청을 처리하는 컨트롤러 상-변수인 reviewsCreate를 만든 틀을 가지고 완성하게 되었습니다.
reviewscreate는 여러 개의 상-변수 함수로 파트들을 구별해서 처리하는 방식을 사용합니다.
각각 하나하나 설명하면 다음과 같습니다.

첫번째는 doSetAverageRating 처리 함수입니다. 이 함수는 장소 문서인 location를 받은 뒤,
if문에서 리뷰들(reviews)이 존재하는 지와 리뷰가 단 하나라도 존재하는 지를 검사한 뒤, count에 리뷰들 배열의 길이인 length를 저장한 뒤,
total이라는 상-변수를 만들어 reduce 메서드를 활용하여 기존 레이팅 총합에 추가하는 리뷰의 레이팅을 추가했습니다.
다음으로 location.rating에 total / count 값을 10진법 기반으로 parseInt로 정수화시켜서 업데이트합니다. (평균 평점으로 계산됩니다.)

다음으로 try문에서 이를 location.save 메서드로 변경한 레이팅 값이 저장된 버전의 location을 저장하는 걸 확정합니다.
만약에 문제가 생기지 않는다면 정상적으로 업데이트가 되었다고 console 로그가 뜨며, 문제가 생긴다면 catch문에서 err를 잡아서
이를 처리한 뒤 에러 정보를 로그로 출력하는 방식으로 만들게 되었습니다.

두번째는 updateAverageRating 처리 함수입니다. 이 함수는 locationId를 받은 뒤,
try-catch문에서 이를 처리합니다. location이라는 const 상-변수를 만든 뒤, 여기에 다음과 같은 코드의 내용을 저장합니다.
Loc.findById(locationId).select('rating reviews').exec();

매개변수로 받은 locationId로 찾은 문서에서 rating과 reviews 부분만 선택한 뒤 exec에 넘겨서 처리하게 만듭니다.
다만 이번에는 다른 함수로 연결해서 하는 일이라 exec 자체 내부는 내용이 없습니다.
선택한 부분을 location에 저장한 뒤, if문을 만나게 합니다. 만약 location이 존재한다면 doSetAverageRating으로 이를 넘깁니다.
넘긴 rating과 reviews 부분은 위에서 서술한 doSetAverageRating에서 잘 사용하게 됩니다.

세번째는 doAddReview 처리 함수입니다. updateAverageRating 처리 함수를 여기서 활용하게 됩니다.
req, res, location 세 개의 인자를 사용하는 처리 함수입니다.
장소 문서가 만약에 if문에서 존재하지 않는다로 걸러진다면 404 에러 코드와 함께 json 에러 메시지를 출력하게 만들었습니다.
return res.status(404).json({ "message": "Location not found" });

걸리지 않는다면 아래에 있는 const문에 가게 됩니다. req.body에서 author, rating, reviewText에 Form에서 입력한 데이터들을
각각 지정하여 사용할 준비를 마칩니다.
이후 location.reviews.push 메서드에 이 세 가지를 묶어서 전달하여 서브 다큐먼트인 리뷰 제작에 사용하게 합니다.

이제 try-catch문에서 가져온 데이터들을 사용하게 됩니다.
먼저, updatedLocation라는 const 상-변수에 save 메서드로 리뷰가 추가된 버전의 location이 저장되게 했습니다.
다음으로 updateAverageRating에 이 updatedLocation의 _id를 저장하여 레이팅이 업데이트된 버전이 나오게 합니다.
마지막으로 thisReview라는 const 상-변수를 만들고 거기에 updatedLocation.reviews.slice(-1).pop() 코드로 맨 마지막 리뷰가 저장되게 했습니다.
맨 마지막 리뷰는 다르게 말하면 가장 최근에 추가한 리뷰, 지금 코드 상에서는 지금 추가한 리뷰이죠.

이 모든 과정에서 오류가 생기지 않으면 return res 문으로 들어가 201 상태 코드를 출력하고 json 메서드로 추가한 리뷰가 띄워지게 됩니다.
오류가 생긴다면 catch문에서 err를 감지하여 400 에러 코드와 err 자체의 정보를 출력하게 만들었습니다.

마지막으로 reviewsCreate 메인 처리 함수입니다. req, res를 사용합니다.
req.params, 즉 URL 파라미터에 있는 locationid를 끌고 와 if (!locationid) 문으로 존재 여부를 검사합니다.
만약에 존재하지 않는다면 return res문으로 404 에러 코드와 json 에러 메시지가 출력되게 만들었습니다.

if문을 통과한다면 locationid가 존재한다는 정상 상황으로 try-catch문에 들어가게 됩니다.
location이라는 const 상-변수를 다시 만듭니다. 이때, findById 메서드에 전달 받은 locationid를 넣어
해당하는 문서를 찾은 뒤 그 문서의 reviews를 select 메서드로 선택하여 exec 메서드로 연결하여 넘깁니다.

다음으로 if-else문에서 location이 정상적으로 존재하는지 if문에서 확인 후 이 location을 doAddReview에 넘기게 됩니다.
그러면 location.reviews를 doAddReview에서 아주 잘 사용하게 됨을 위의 설명에서 확인하실 수 있습니다.
만약 location이 존재하지 않는다면 else문에서 return res문으로 404 에러 코드와 json 에러 메시지가 출력되게 됩니다.

최종적으로 이 모든 과정에서 에러가 생긴다면 catch (err) 문에서 이 에러를 감지하여 400 에러 코드와 같이 err 자체의 정보를 출력하게 됩니다.
