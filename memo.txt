마지막 과제입니다. 4번 과제에서 하던 지리 정보 처리 작업을 계속 진행합니다.
지금까지 하던 모든 지리 정보 처리 작업을 모두 진행한 결과는 다음과 같습니다.

URL에 쿼리 스트링으로써 URL 파라미터 자체의 좌표 값 비설정을 해결할 수 있으며,
직접 위도와 경도를 URL에 명시해서 하면 이를 활용할 수 있게 했습니다.

일반적으로 쿼리 스트링으로 명시한 것들은 req.query에서 가져올 수 있습니다.

다만, URL에 명시한 위도와 경도는 어쨌든 스트링이라 이를 처리할 수 있는 숫자로
변환하기 위해 JS 자체의 parseFloat 함수를 이용하여 변환을 하게 했습니다.
예) const lng = parseFloat(req.query.lng);

lng, lat를 모두 변환한 후 near에 넣어줍니다.
near는 우리가 탐색하는 데 사용되는 기준으로써 작용합니다.
지리 정보 처리 작업의 핵심은 URL의 쿼리 스트링을 가지고 장소들에서 그 기준점에서의
거리를 계산하여 장소와 같이 명시하는 것이 핵심이니까요.
탐색 기준으로 사용하기 위해 type은 "Point" (기준점),
좌표 값인 lng,lat는 coordinates에 넣어줬습니다.

이후 지리 탐색에서 사용할 옵션인 geoOptions를 지정합니다.
지정할 옵션은 다음과 같습니다.
첫번째는 distanceField, 거리가 저장되는 공간의 이름을 정합니다.
두번째는 key, 탐색에 사용되는 키로써 추후 외부 API와의 연계에서 사용 가능합니다.
지금 당장은 'coords'로 세팅했습니다.
세번째는 spherical, 이를 true로 해두면 구형 탐색으로 탐색을 설정할 수 있습니다.
당연히 지구는 어느 정도의 구형이니 이를 켜둬야합니다.
네번째는 maxDistance로, 미터 단위의 값을 지정하여 최대 얼마의 거리까지 갈 지를
탐색 거리를 지정할 수 있습니다. 20000m로 세팅했습니다.

한편, 애초에 URL에 좌표 값이 명시되지 않았을 수도 있을 상황을 막기 위해
if (!lng || !lat) 문을 만들어서 이 상황을 막게 했습니다.
이 경우 return res문으로 들어가 404 에러 코드와 lng와 lat 값이 필요하다는
메시지를 출력하도록 status와 json 메서드를 세팅했습니다.

이제 try-catch문으로 넘어갑니다, 여기서 요청을 처리하게 됩니다.
우리의 핵심은 지리 좌표 명시로도 GET 요청을 정상적으로 처리하는 겁니다.

최종 결과는 locations긴 합니다, 왜냐하면 명시한 좌표 값을 기준으로써 거리를 계산하되,
location, 즉 장소 하나하나의 정보와 같이 출력하기 때문이죠.
일단은 results부터 만들게 했습니다.

우리가 명시한 최대 거리까지의 주변 장소를 찾고 거리를 명시해주는 건
결국 Loc.aggregate가 하는 일입니다.

이제 aggregate 메서드에 $geoNear를 기재합니다.
그동안 세팅해 온 near와 geoOptions를 내부에 적었습니다.
이 때 geoOptions를 추가할 때 ...을 붙여서 내부에 적게 됩니다.
이러는 이유는 geoOptions가 배열인데, 사실 여러 옵션을 묶어둔 거라
이를 풀어서 적용시켜야하기 때문입니다.
그래서 Spread operator를 이용하여 이 배열을 하나하나 풀어서
여러 인자로 확장해서 적용하게 했습니다.

results에 이제 모든 장소들이 탐색되어 저장됩니다.
한편, 반환된 장소+거리 데이터는 상당히 큰 데이터라서
의미 있고 최소화할 필요가 있다.

따라서 map 메서드를 활용하여 results를 다시 처리하게 됩니다.
그 안의 result 하나하나의 데이터 구조를 재구성합니다.
_id, name, address, rating, facilities, distance
총 6가지의 구성 요소에 result 하나하나의 매칭되는 데이터 한 개씩
지정합니다.

이 때, distance에는 `${result.distance.calculated.toFixed()}m`를
사용합니다. 계산된 데이터 거리 자체는 소수점이 포함된 거리라서
이 거리를 정수형으로 전환하기 위해 toFixed 메서드를 사용하여
깔끔하게 소수점을 제거합니다. 거리 단위는 m이니 m를 명시합니다.
*$은 치환 역할을 합니다, 자동으로 갈아끼워집니다.

이후 재구성한 locations를 응답으로써 출력하게 됩니다.
status로 200 상태 코드를 출력하고, json으로 locations를 출력했습니다.

마지막으로 애초에 이 모든 과정에서 명시하지 않은 에러가 발생한 경우,
err를 catch문에서 처리하여 404 에러 코드와 에러 자체를 출력하게 했습니다.

아래의 기존 locationsReadOne과 나머지 틀 및 exports는 동일합니다.
